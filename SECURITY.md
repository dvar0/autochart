# Reporting a security issue

For ordinary bugs, use GitHub Issues. For a vulnerability that could expose
private data, execute unintended code, or read/write files outside the intended
storage boundaries, use **Security → Advisories → Report a vulnerability** in
this repository when available.

If that private reporting option is unavailable, open an issue asking for a
private contact method without including vulnerability details. Do not post
credentials, private files, or an exploit in a public issue.

A useful private report includes the app version, OS/architecture, reproduction
steps, expected and observed behavior, and impact. A minimal synthetic file is
preferable to someone else's song library or personal data.

This is a hobby project with no guaranteed response time or paid bug bounty.
Fixes target the latest release; older versions do not have a separate maintenance
schedule.
